# USDT payments with NOWPayments

The academy accepts only `USDT` on TRON/TRC20 (`usdttrc20`). Course identifiers are the only checkout input accepted from the browser. Prices, settlement asset, network, callback URL, and browser-return URLs are generated by the server.

Configure `NOWPAYMENTS_API_KEY`, `NOWPAYMENTS_IPN_SECRET`, and an HTTPS `NOWPAYMENTS_CALLBACK_URL` ending in `/api/webhooks/payments`. `NOWPAYMENTS_API_BASE_URL` defaults to `https://api.nowpayments.io/v1`; non-production certification may explicitly use `https://api-sandbox.nowpayments.io/v1`. Production rejects any non-production API endpoint.

Checkout creates a durable `PENDING` purchase before contacting NOWPayments. The provider payment ID, expected/received amounts, wallet address, network, provider status, transaction hash, expiry, and webhook hash are stored on `Purchase`.

Create Payment sends only server-controlled `price_amount`, `price_currency=usd`, `pay_currency=usdttrc20`, callback URL, immutable Purchase ID as `order_id`, and order description. Integer cents are formatted directly as a two-decimal USD string without floating-point division. The provider client performs one request with a ten-second timeout and does not retry payment creation.

IPN bodies are verified using NOWPayments' alphabetically sorted canonical JSON and an HMAC-SHA512 constant-time comparison. Duplicate events are idempotent. A reused event identity with a different payload is rejected.

Only NOWPayments `finished` events are eligible to become `PAID`, and only when the received amount is at least the expected amount. `waiting`, `confirming`, `confirmed`, `sending`, and `partially_paid` remain `PENDING`. The webhook's payment ID, order ID, payment address, quoted USDT amount, price amount/currency, payment currency, and TRC20 network must match the stored purchase. Underpayments remain `PENDING`; overpayments are accepted.

Normal transitions are `PENDING` to a terminal business state, `PAID` to `REFUNDED`, and a final, fully bound late `finished` event from `EXPIRED` or `CANCELLED` to `PAID`. A `REFUNDED` purchase cannot return to `PAID`. Refunds revoke only enrollments currently associated with that purchase.

The provider exposes an internal, read-only `getPaymentStatus(paymentId)` capability for sandbox checks and future reconciliation. It does not update purchases or grant enrollment.

The browser may poll `GET /api/purchases/:id`, which is ownership scoped. Polling never grants access. Only the verified webhook transaction creates enrollment.

Do not log API keys, full IPN bodies, or payment addresses. Operational logs should use the internal purchase ID and provider status.

Each Pay request intentionally creates a new Purchase and NOWPayments payment attempt. The browser disables the button while its request is active, but separate requests or tabs can create separate attempts. Coupon reservations expire after 30 minutes, and provider expiry IPNs close stale payment attempts. A stronger cross-request idempotency key is deferred because it would change the checkout contract.

NOWPayments payment creation and local persistence cannot be atomic. If remote creation succeeds but persistence fails, the route records a safe diagnostic containing only purchase/payment identifiers, retries local preservation once as a failed purchase, releases any coupon reservation, returns a generic error, and grants no enrollment. Phase 4 reconciliation must inspect any remaining external orphan payments.
